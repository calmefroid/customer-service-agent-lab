# 04 对话任务简报：消费者端交互

## 可直接发给新对话的首条消息

> 你负责“客服 Agent 实验室”的手机消费者端体验。请在 `feat/consumer-experience` 对应 worktree 工作，并等待 01 对话的 AgentEvent v1 稳定后接入。先阅读并行计划、PRD 和当前页面。只修改本简报允许的文件；不要修改模型、业务 Adapter、知识后台、Trace 或公共 contracts。

## 目标

把当前固定延时的对话页升级为真实事件驱动的手机客服体验，同时保持三个快捷入口和售后定位。

## 允许修改

- `src/app/page.tsx`
- `src/app/globals.css`
- `src/components/chat/**`
- `src/lib/public-progress.ts`
- `src/app/api/feedback/**`
- `src/lib/stores/feedback-store.ts`
- `tests/consumer/**`

## 功能清单

- 拆分消息、进度、图片、确认、订单、退换、报修、安全和知识卡片。
- 消费 AgentEvent 流，阶段状态来自服务端事件。
- 停止生成、重新发送、失败重试。
- 图片选择、预览、移除、上传中、识别中、失败和重试。
- 写操作统一确认卡：修改、取消、确认。
- 赞 / 踩、是否解决和负反馈原因，写入本地反馈 Store。
- 键盘、窄屏、滚动、错误态和 reduced motion。
- 永远不展示 Prompt、工具参数、知识条目或规则证据。

## 关键测试

- 流式阶段按事件顺序更新。
- 停止后 UI 回到可发送状态。
- 重试保留原始文字和图片。
- 失败不显示虚假成功卡。
- 取消确认不调用提交接口。
- 消费者 DOM 不含后台 debug 字段。

## 不做

- 不定义 AgentEvent。
- 不改业务判断和知识排序。
- 不增加第四个快捷入口。

## 交付

- 手机窄屏和桌面手机框浏览器验收。
