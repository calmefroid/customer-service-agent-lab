# 05 对话任务简报：客服运营台

## 可直接发给新对话的首条消息

> 你负责“客服 Agent 实验室”的客服运营台。请在 `feat/operations-console` 对应 worktree 工作，并基于 02 对话提供的只读 Store 接口实现 `/ops`。先阅读并行计划、PRD 和现有 Trace / knowledge 后台的视觉语言。只新增 ops 相关目录，不修改消费者页、业务 Store 内部、公共 contracts 或 Trace 页。

## 目标

让客服、产品和测试人员可以查看 Sandbox 中产生的业务单据、异常和风险会话，并追溯到来源会话 / Trace。

## 允许修改

- `src/app/ops/**`
- `src/app/api/ops/**`
- `src/lib/operations/**`
- `tests/operations/**`

## 功能清单

- 异常订单、物流催办、退换申请、维修 / 安装工单、人工接管、风险会话。
- 总览统计、类型 / 状态 / 风险 / 渠道 / 时间筛选。
- 列表 + 详情。
- 来源系统、更新时间、关联 sessionId / traceId。
- 跳转到 Trace，并支持 Trace 按 ID 定位的 URL 参数建议。
- loading、empty、API error、source degraded。
- 明确 Sandbox / Mock 标识。

## 关键测试

- 写入一条催办后能在运营查询接口找到。
- 风险会话按 high 筛选。
- 详情返回关联 Trace。
- 不返回未脱敏手机号和地址。
- Store 空时页面有明确空态。

## 不做

- 不修改或处理真实单据。
- P0 不做登录、RBAC 和批量操作。
- 不复制 Trace 的模型调试详情。

## 交付

- `/ops` 页面和只读 API。
- 一条从消费者操作到运营台再到 Trace 的浏览器验收路径。
- 一次独立提交。
